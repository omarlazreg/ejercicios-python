# _**Agenda y gestor de tareas diario**_

**Restricciones:** el uso de IA está terminantemente prohibido. Nada del código escrito debe ser redactado por IA.

La IA actúa como tutor disponible 24/7 pero no debe escribir nada de codigo y debe ser evitada al máximo en cualquier tarea, a poder ser incluso para las explicaciones.

Se recomienda buscar en google, stack overflow, leer documentación... aunque es mucho más pesado y en la práctica profesional no se trabajará así, en esta fase se maximiza el aprendizaje leyendo, investigando, etc. 

Intentar en todo caso reflexionar antes de preguntarle a la IA durante un rato, y priorizar la organización y estructura del proyecto por ti mismo. 

### Gestion del proyecto

Los proyectos de programación sin un sistema claro se deterioran. Vuelves después de dos semanas y tardas una hora en reconstruir el contexto. Las tareas se acumulan sin orden de prioridad. Las ideas entran al pipeline sin evaluación previa. Y en algún punto el proyecto pasa de “activo” a “pausado” sin que hayas tomado esa decisión conscientemente.


### Estructura 

    Problema -> Misión -> Objetivo -> Plan -> Tareas

**Definición del problema:** cada vez que recuerdo que debo hacer algo, o surge cualquier tarea, debo parar lo que estoy haciendo para ir al correo, apuntarlo en el calendario, etc. Perdiendo más tiempo del necesario. 

**Misión:** Maximizar la organización y optimización diaria, evitando perder tiempo entrando en el correo, guardando, entrar a consultarlo, etc.

**Objetivo:** Crear a través de terminal un programa que al llamarlo con un comando, nos pregunte qué tarea queremos guardar. Escribiremos la tarea y la información necesaria para guardarla en un archivo consultable. 

**Plan:** dado que este proyecto es básico y super pequeño, el plan no es más que ceñirse a las tareas definidas abajo.

**Tareas:** Unidades mínimas de trabajo concreto, tamaño definido y resultado verificable.


### Diagrama de flujo

1. Disparador: surge idea/necesidad de tarea
2. Captura: se registra la tarea (dónde, quién, formato, durante cuánto tiempo)
3. Clasificación/priorización: categoría, urgencia, responsable
4. Asignación: a persona/equipo
5. Ejecución.
6. Validación/revisión: ¿se ha realizado la tarea? Check de calidad o aprobación
7. Cierre: se marca como completada o como fracasada.
8. Archivo: se guarda en el sistema final.  

### Tareas específicas

1. Llamar al programa mediante un comando en terminal
2. Mostrar una lista de todas las tareas pendientes ordenadas por fecha ascendente (las cercanas primero)
3. Escribir la tarea/idea que queremos guardar.
4. Asignar Categoría,fecha, hora, acompañantes, lugar, observaciones de la tarea
5. Comprobar si ya hay alguna tarea a esa hora
